# 블로그 기본 레이아웃 (blog-layout) 기획안

## 요약
Vite 기본 화면에 있는 요소와 CSS를 모두 지우고, 개인 개발 블로그의 뼈대를 만든다. 화면은 메뉴(헤더), 글 목록, 글 본문, 글쓰기 네 영역으로 나눈다.
새 의존성 없이 `App`의 `useState` 하나로 "목록 / 본문 / 글쓰기" 화면을 전환한다. 데이터는 코드에 넣은 예시 글을 쓴다.
범위는 위치 잡기까지다. 저장, 서버 연동, 디자인 다듬기는 하지 않는다.

## 개발자에게 확인할 질문
1. **화면 전환 방식**: 주소(URL)가 바뀌는 라우팅(react-router 등 새 의존성)이 필요한가, 아니면 상태 전환으로 충분한가?
   - 추천 답: 지금은 상태 전환으로 충분하다. 새로고침하면 목록 화면으로 돌아가는 제약은 받아들인다. 라우팅은 실제 글 데이터를 붙일 때 별도 기능으로 다룬다.
2. **데스크톱 배치**: (A) 헤더 메뉴 + 본문 영역 하나에 목록/본문/글쓰기를 번갈아 표시, (B) 헤더 메뉴 + 왼쪽 목록 사이드바 + 오른쪽 본문, 둘 중 무엇으로 할까?
   - 추천 답: (B). 데스크톱(1280px)에서는 목록을 왼쪽에 항상 두고 오른쪽에 본문이나 글쓰기를 보여준다. 모바일(375px)에서는 한 열로 쌓아 목록 아래에 본문이 오게 한다. 개발 블로그에서 흔한 형태이고 "목록"과 "본문"의 위치가 한눈에 보인다.
3. **"CSS 다 비우기"의 범위**: 위치를 잡으려면 최소한의 레이아웃 CSS가 필요하다. 기존 내용을 모두 지운 뒤 레이아웃용 규칙(grid/flex, 간격, 포커스 표시)만 새로 넣어도 되는가?
   - 추천 답: 된다. `index.css`는 기본 리셋 몇 줄만 남기고, `App.css`에는 레이아웃 규칙만 둔다. 색, 폰트, 장식은 넣지 않는다.
4. **기본 템플릿 자산 삭제**: `src/assets/hero.png`, `react.svg`, `vite.svg`, `public/icons.svg`를 삭제하고 `index.html`의 `<title>`을 바꿔도 되는가?
   - 추천 답: 쓰지 않게 되는 자산 4개는 삭제한다. `favicon.svg`는 남긴다. `<title>`은 "개발 블로그"로 바꾼다(블로그 이름이 정해져 있으면 알려 달라).
5. **글쓰기 화면의 저장 버튼**: 아직 저장 기능이 없는데 버튼을 어떻게 둘까?
   - 추천 답: 제목과 본문 입력칸, "저장" 버튼까지 배치만 한다. 버튼은 비활성(disabled)으로 두고 옆에 "저장 기능은 준비 중입니다"라고 적는다. 눌렀는데 아무 일도 없는 버튼은 만들지 않는다.

## 완료 기준
- [ ] 화면에 Vite/React 기본 요소(로고, 카운터 버튼, Documentation/Connect 영역)가 하나도 보이지 않는다.
- [ ] 기존 `App.css`, `index.css` 내용이 모두 지워지고, 질문 3에서 승인된 레이아웃 규칙만 남는다.
- [ ] 모든 화면 상단에 블로그 이름과 메뉴("글 목록", "글쓰기")가 있는 헤더가 보인다.
- [ ] 처음 열면 글 목록이 보이고, 예시 글 제목들이 나열된다.
- [ ] 목록에서 글 제목을 누르면 그 글의 제목, 날짜, 본문이 본문 영역에 보인다.
- [ ] 메뉴의 "글쓰기"를 누르면 제목 입력칸, 본문 입력칸, 비활성 "저장" 버튼이 보인다. 두 입력칸에는 보이는 라벨이 있다.
- [ ] 메뉴의 "글 목록"을 누르면 처음 화면으로 돌아간다.
- [ ] 예시 글 배열이 비어 있으면 목록 영역에 "아직 글이 없습니다. 첫 글을 써보세요"와 글쓰기로 가는 버튼이 보인다.
- [ ] 마우스 없이 Tab/Enter만으로 메뉴 이동, 글 선택, 글쓰기 진입이 모두 가능하고 포커스 위치가 보인다.
- [ ] 375px 폭에서 가로 스크롤이 생기지 않고 영역이 세로로 쌓인다. 1280px에서는 질문 2에서 정한 배치로 보인다.
- [ ] `yarn lint`, `yarn build`, `yarn test`가 통과한다.

## 화면과 상태
데이터는 코드에 넣은 예시 글(동기 상수)이라 실제 로딩과 에러가 생기지 않는다. 그래서 로딩과 에러 화면은 이번 범위에서 만들지 않고, 데이터를 연결하는 기능에서 다룬다(엣지 케이스 E4 참고).

| 화면/영역 | 로딩 | 빈 상태 | 에러 | 정상 |
|---|---|---|---|---|
| 헤더(메뉴) | 해당 없음 | 해당 없음 | 해당 없음 | 블로그 이름, "글 목록", "글쓰기" 버튼. 지금 보는 메뉴에 `aria-current="page"` 표시 |
| 글 목록 | 해당 없음(정적 데이터) | "아직 글이 없습니다. 첫 글을 써보세요" + "글쓰기" 버튼 | 해당 없음 | 글 제목과 날짜를 최신순으로 나열. 선택된 글에 표시 |
| 글 본문 | 해당 없음 | 선택된 글이 없으면(데스크톱 B안 첫 화면) "왼쪽 목록에서 읽을 글을 고르세요" | 선택한 id의 글이 없으면 "글을 찾을 수 없습니다" + 목록으로 돌아가기 | 제목, 날짜, 본문 텍스트 |
| 글쓰기 | 해당 없음 | 빈 입력칸(placeholder 안내) | 해당 없음 | 라벨이 붙은 제목/본문 입력칸, 비활성 "저장" 버튼과 준비 중 안내 |

## 엣지 케이스
- [필수] 판단: 템플릿 자산을 지울 때 import가 남아 있으면 빌드가 깨진다. App.tsx의 asset import를 모두 지운 뒤 파일을 삭제한다.
  - 근거: `src/App.tsx` 2~4행이 `hero.png`, `react.svg`, `vite.svg`를 import하고, 37~107행이 `/icons.svg`를 참조한다.
  - 검토한 대안: 자산 파일을 남겨 두는 방법. 동작은 하지만 "요소 다 지워주고"라는 요청에 맞지 않아 택하지 않았다.
  - 확신도: 높음
  - 사람이 결정할 것: 자산 삭제 여부(질문 4)
- [필수] 판단: CSS를 완전히 비우면 목록/본문/글쓰기의 위치가 구분되지 않아 요청한 "위치 잡기"가 불가능하다. 레이아웃용 최소 CSS는 필요하다.
  - 근거: `docs/features/blog-layout/request.md`("css파일도 다 비워주고"와 "러프하게 위치 잡아주라"가 함께 있음)
  - 검토한 대안: 인라인 style 사용. CSS를 비웠다는 형식은 지키지만 실제로는 스타일이 옮겨 갈 뿐이고 반응형(미디어쿼리)을 할 수 없어 택하지 않았다.
  - 확신도: 중간
  - 사람이 결정할 것: 질문 3
- [권장] 판단: 메뉴와 목록 항목은 `<a href>`가 아니라 `<button type="button">`으로 만든다. 주소 이동이 없으니 링크를 쓰면 키보드, 스크린리더 사용자에게 잘못된 안내가 된다.
  - 근거: `docs/agents/ux-principles.md` 접근성 항목. 라우팅을 쓰지 않기로 한 질문 1의 추천 답.
  - 검토한 대안: `href="#"` 링크. 새로고침이나 뒤로가기를 했을 때 기대와 다르게 동작해서 택하지 않았다.
  - 확신도: 중간(질문 1에서 라우팅을 고르면 링크로 바꾼다)
- [권장] 판단: 375px에서 긴 영문 제목이나 코드 같은 긴 문자열이 가로 스크롤을 만들 수 있다. 본문 영역에 `overflow-wrap: anywhere`을 둔다.
  - 근거: 개발 블로그라 긴 영문 식별자가 많을 것으로 예상. `ux-principles.md` 반응형 기준 375px.
  - 검토한 대안: 이번에는 무시하는 방법. 규칙 한 줄로 막을 수 있어 넣는다.
  - 확신도: 중간
- [참고] 판단: 상태 전환 방식이라 새로고침하거나 뒤로가기를 하면 첫 화면(목록)으로 돌아간다. 이번 범위에서는 받아들인다.
  - 근거: 질문 1. `package.json`에 라우팅 라이브러리가 없음.
  - 검토한 대안: `history.pushState`를 직접 다루는 방법. 위치 잡기 범위를 넘어서 택하지 않았다.
  - 확신도: 높음
- [참고] 판단(E4): 로딩과 에러 상태는 정적 데이터라 이번에 만들지 않는다. 데이터를 연결할 때 목록 영역에 추가한다.
  - 근거: CLAUDE.md "로딩, 빈 상태, 에러 상태를 항상 고려한다". 이번 기능에는 비동기 데이터가 없다.
  - 검토한 대안: 쓰이지 않는 가짜 로딩 UI를 미리 만드는 방법. 요청하지 않은 추가라서 택하지 않았다.
  - 확신도: 중간

## 구현 계획
새 의존성은 없다. 상태는 공통 부모인 `App`에 둔다(CLAUDE.md 규칙). 컴포넌트는 파일 하나에 하나씩, PascalCase 파일명으로 만들고 기능 폴더 `src/features/blog/`에 넣는다.

| 파일 | 작업 | 책임 |
|---|---|---|
| `src/App.tsx` | 전면 교체 | 상태 2개를 가진다. `view: 'list' \| 'post' \| 'write'`, `selectedPostId: string \| null`. 헤더, 목록, 본문/글쓰기 영역을 배치하고 전환 핸들러를 넘긴다. 선택된 글은 id로 찾아 계산하고 상태에 따로 두지 않는다(`architecture.md`). |
| `src/App.css` | 비운 뒤 재작성 | 레이아웃 규칙만 둔다. 헤더, 사이드바+본문 grid(1280px 기준), 768px 미만에서는 한 열, `:focus-visible` 외곽선, 버튼 최소 높이 44px. |
| `src/index.css` | 비운 뒤 재작성 | `box-sizing`, `body` margin 0 등 리셋 몇 줄만 둔다. |
| `src/features/blog/types.ts` | 신규 | `Post { id: string; title: string; date: string; body: string }`, `BlogView` 타입 |
| `src/features/blog/samplePosts.ts` | 신규 | 예시 글 3개를 담은 `Post[]` 상수 |
| `src/features/blog/BlogHeader.tsx` | 신규 | 블로그 이름, "글 목록"/"글쓰기" 버튼(`<header><nav>`). 지금 화면에 `aria-current` 표시 |
| `src/features/blog/PostList.tsx` | 신규 | `posts`, `selectedPostId`, `onSelect`, `onWrite`를 받는다. 목록 또는 빈 상태를 보여준다. |
| `src/features/blog/PostDetail.tsx` | 신규 | `post: Post \| undefined`를 받는다. 본문, 선택 안내, "글을 찾을 수 없습니다" 중 하나를 보여준다. |
| `src/features/blog/PostEditor.tsx` | 신규 | 라벨이 붙은 제목/본문 입력칸, 비활성 저장 버튼과 준비 중 안내. 입력값은 저장하지 않으므로 비제어 입력으로 둔다. |
| `src/assets/hero.png`, `react.svg`, `vite.svg`, `public/icons.svg` | 삭제(질문 4 승인 시) | 사용하지 않는 템플릿 자산 |
| `index.html` | `<title>`만 수정(질문 4 승인 시) | 탭 제목 |
| `src/main.tsx` | 변경 없음 | |

로직이 짧아서 커스텀 훅은 만들지 않는다(`architecture.md` 기준: 20줄을 넘을 때 분리를 검토).

## 테스트 계획
- 단위 테스트: 이번 기능에는 로직이 있는 훅이나 유틸이 없다. 그래서 `architecture.md` 기준으로는 단위 테스트가 필수가 아니다. `yarn test`는 `--passWithNoTests`로 통과한다.
  - [참고] 화면 동작(메뉴 전환, 빈 상태)을 자동 테스트하려면 `@testing-library/react`와 `jsdom`이 필요하다. 현재 `package.json`에는 둘 다 없다. 새 의존성이라 이번 범위에서는 추가하지 않고, 필요하면 개발자가 승인한 뒤 추가할 것을 제안한다.
- 사용 시나리오(qa-customer가 브라우저에서 확인):
  1. 처음 접속하면 기본 Vite 요소 없이 헤더와 글 목록이 보인다.
  2. 목록에서 두 번째 글을 누르면 그 글의 제목과 본문이 보이고, 목록에 선택 표시가 생긴다.
  3. 헤더의 "글쓰기"를 누르면 입력칸 2개와 비활성 저장 버튼, 준비 중 안내가 보인다.
  4. 헤더의 "글 목록"을 누르면 처음 화면으로 돌아간다.
  5. 마우스 없이 Tab/Enter만으로 1~4를 반복할 수 있고 포커스 위치가 항상 보인다.
  6. 375px와 1280px 폭에서 각각 배치를 확인한다. 375px에서 가로 스크롤이 없어야 한다.
  7. (개발자 확인) `samplePosts`를 빈 배열로 바꾸면 빈 상태 안내와 글쓰기 버튼이 보인다.
- 정적 검증: `yarn lint`, `yarn build`, `yarn test`

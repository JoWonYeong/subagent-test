## 구현 화면 UX 검토 결과 (blog-layout)
[필수] 0개, [권장] 2개, [참고] 4개

확인 방법: Playwright로 http://localhost:5173 을 1280px와 375px에서 열었고, 목록→글 선택→글쓰기→글 목록 순으로 눌러 봤습니다. `src/App.css`와 컴포넌트 소스도 대조했습니다.
- 스크린샷이 한 단계 늦게 찍히는 경우가 있었습니다. 상태 판단은 접근성 스냅샷을 기준으로 했습니다.
- 키보드(Tab/Enter)만으로 직접 조작해 보지는 않았습니다. 포커스는 클릭 뒤 활성 요소를 스냅샷으로 확인하고, 포커스 표시는 CSS 규칙으로 확인했습니다.

### 기획안과 일치한 항목
- 1280px 첫 화면은 헤더, 왼쪽 목록 3건(최신순, YYYY-MM-DD), 오른쪽 "목록에서 읽을 글을 고르세요" 구성입니다. Vite 기본 요소는 없습니다.
- 글을 누르면 그 글의 제목, 날짜, 본문이 보이고 포커스가 `h2`로 갑니다(스냅샷의 `[active]` heading). 선택 항목은 굵게 표시됩니다.
- 글쓰기 화면에는 저장 불가 안내, 라벨이 있는 제목/본문 입력칸, 비활성 "저장" 버튼, "저장 기능은 준비 중입니다"가 보입니다. 포커스는 `h2`로 갑니다. `aria-describedby`도 연결돼 있습니다.
- 375px에서는 한 번에 한 영역만 보입니다.
  - 목록만 보이는 화면에서 글을 누르면 본문만 보이고, "목록으로" 버튼이 맨 위에 있습니다.
  - 글쓰기를 누르면 글쓰기만 보입니다.
  - 가로 스크롤은 없습니다. 긴 영문 제목은 목록에서 줄이 바뀌어 보입니다.
- 헤더에서 `h1`, `nav` "주 메뉴", `main`, `h2` 구조가 맞습니다. 버튼은 `min-height: 44px`입니다.

### 판단 기록
- [권장] 판단: 글쓰기 화면의 제목/본문 입력칸 높이를 44px 이상으로 키운다.
  - 근거: 375px 스크린샷에서 제목 입력칸 높이가 약 20px입니다. `src/App.css`의 `min-height: 44px`는 `button`에만 걸려 있습니다. `docs/agents/ux-principles.md`의 "터치 영역 최소 44px" 기준에 못 미칩니다.
  - 검토한 대안: 이번 범위(러프한 위치 잡기)라고 보고 넘기는 방법. 입력칸은 모바일에서 누르기 가장 어려운 곳이고 규칙 한 줄(`.post-editor input { min-height: 44px }`)이면 고쳐져서 택하지 않았습니다.
  - 확신도: 높음
- [권장] 판단: 데스크톱에서는 본문 위의 "목록으로" 버튼을 숨기거나, 모바일에서만 보이게 한다.
  - 근거: 1280px에서 글을 열면 목록이 옆에 항상 보이는데도 "목록으로" 버튼이 본문 위에 나옵니다(스냅샷 `button "목록으로"`). 눌러도 선택만 해제되어, 목록이 이미 보이는 상태에서 헷갈립니다. 기획안(`plan.md` 구현 계획, PostDetail)은 "맨 위 목록으로 버튼"만 정했고, 데스크톱 표시 여부는 언급이 없습니다.
  - 검토한 대안: 그대로 두는 방법. 막히지는 않고 기획안에도 위배되지 않아 [필수]는 아닙니다.
  - 확신도: 중간
  - 사람이 결정할 것: 데스크톱에서 버튼을 숨길지 여부
- [참고] 판단: 모바일에서 "목록으로"나 헤더 "글 목록"으로 돌아간 뒤의 포커스 위치는 구현되지 않았습니다.
  - 근거: `plan.md`에서 이번 범위 제외로 결정한 항목입니다. 구현도 그대로입니다.
  - 확신도: 높음
- [참고] 판단: 헤더의 현재 위치 표시가 약합니다.
  - 근거: `aria-current="page"`는 맞게 붙어 있습니다(`src/features/blog/BlogHeader.tsx` 16, 19행). 하지만 눈으로 구분되는 규칙은 `src/App.css`에 없습니다. 스크린샷에서 현재 메뉴가 약간 어둡게 보인 것은 브라우저 기본 모양(마우스를 올린 상태 등)으로 보이고, 의도한 표시가 아닙니다. 선택된 글은 굵은 글씨 규칙이 있는데 헤더에는 같은 규칙이 없습니다.
  - 검토한 대안: 지금 `[aria-current='page'] { font-weight: bold }` 한 줄을 넣는 방법. 목록 항목 규칙과 일관되지만 필수는 아닙니다.
  - 확신도: 중간
- [참고] 판단: 글쓰기 화면의 간격이 고르지 않습니다.
  - 근거: "글쓰기" `h2`와 저장 불가 안내 사이는 넓습니다. 반면 제목 입력칸 바로 아래에 "본문" 라벨이 붙어 있어 어느 입력칸의 라벨인지 헷갈릴 수 있습니다(1280px, 375px 스크린샷 모두 동일).
  - 확신도: 중간
- [참고] 판단: 비활성 "저장" 버튼의 글자색이 옅습니다.
  - 근거: 스크린샷에서 흐린 회색으로 보입니다. 비활성 버튼이라 대비 기준에서 제외되는 것이 일반적이고, 의미는 옆의 "저장 기능은 준비 중입니다"가 전달합니다.
  - 확신도: 중간

# 구조 원칙 (code-reviewer가 읽음)

## 레이어
- 컴포넌트: 화면 표시와 사용자 입력 처리만 한다.
- 훅: 상태 로직과 부수 효과를 담는다. 컴포넌트에서 로직이 20줄을 넘으면 훅으로 분리를 검토한다.
- 타입: 기능 전용 타입은 기능 폴더에, 공통 타입은 `src/types/`에 둔다.

## React
- 파생 가능한 값은 상태로 두지 않고 계산한다.
- useEffect는 외부 시스템과 동기화할 때만 쓴다. 상태를 다른 상태로 옮기는 용도로 쓰지 않는다.
- React Compiler를 사용하므로 useMemo, useCallback을 습관적으로 쓰지 않는다.
- 리스트 key에 index를 쓰지 않는다 (순서가 바뀌는 리스트의 경우).

## 금지 패턴
- `any`, `@ts-ignore`
- 컴포넌트 안에서 직접 fetch (훅으로 분리)
- 요청받지 않은 전역 상태 라이브러리 도입
- 테스트 없이 로직이 있는 훅 추가

## 테스트
- 로직이 있는 훅과 유틸에는 단위 테스트를 둔다.
- 테스트는 구현 세부가 아니라 사용자에게 보이는 동작을 검증한다.
